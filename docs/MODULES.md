# 模块扩展约定

生产 Worker 入口是 src/index.ts。third_party 中的旧独立 Worker 不是路由入口。

## 当前结构

- src/core/registry.ts：集中注册模块 manifest、配置字段、执行、只读探测、复核函数。
- src/modules/<module>/adapter.ts：把原项目结果映射为 succeeded / already_done / failed / waiting_verification。
- src/core/identity.ts：只读平台身份探测；用户声明的 UID 或 Cookie 文本本身不可信。
- src/durable/account-coordinator.ts：同账号串行化、检查点与任务恢复；B站待兑换保护仍有专项逻辑。
- 前端由 manifest.configSchema 展示基础 boolean/integer 设置字段；后端 validateModuleSettings 再次验证。

## 新增一个普通平台

1. 编写 adapter、manifest、configSchema、只读身份探测及凭据校验。当前凭据编辑器适配 Cookie / CUID / 安全 Header；非Cookie平台应扩展对应凭据字段。
2. 注册到 registry，并为身份探测增加固定白名单端点，不能让普通用户选择任意网络地址。
3. 加入模块ID校验与管理员开关，确认前端显示和类型一致。
4. 使用统一 TaskResult，不直接向其他用户的通知渠道发送消息。
5. 增加正常、已完成、失效Cookie、超时、越权和重投测试，再发布代码。

## 新增资金/资产型平台

不能只注册一个“消费”函数就认为安全。当前安全锁针对 B 站请求和报告字段，新的非幂等接口需要设计自己的：
- 请求前持久化意图、操作ID和真实账号锁；
- 响应未知后的只读核验；
- 消费限额、前后余额/订单证据与用户确认；
- 不可确定时禁止再次提交的策略；
- 兼容升级与删号保护。

这是代码级模块化，不是动态插件商店，也不是允许用户上传任意JavaScript执行。

## 模块公共边界

- 新任务必须通过 `queueRunBatch` 建立运行记录与 outbox；同账号兑换依赖领取完成，禁止由适配器自行绕过协调器重试未知结果的非幂等操作。
- 批量调用最多 20 个任务。用户手动/自动额度写入独立使用账本，删除账号或任务不会退还近期额度。
- 所有凭据更新均先只读确认平台真实身份，更新现有账号不能变更平台 UID。组、账号、计划、审计及扫码消费在事务中提交。
- 结果可确定时采用只读 `reconcile`；缺乏证据时保留 `waiting_verification`。新增资金型模块需要独立证据模型，不能复用不匹配的余额推断。
- 组通知 `null` 表示继承用户默认策略；显式空渠道表示关闭，不得把用户的关闭选择自动迁移为开启。
- 网络端点白名单、响应上限、取消/超时和 Cookie 域隔离属于适配器边界。新增重定向必须逐跳验证目标，不转发跨域凭据。
- 模块禁用后仍保留历史数据和凭据管理入口，但执行、扫码和上游调用必须检查模块及维护开关。
- 管理员人工结案只能记录经证据核实的既有结果，必须保留不可变证据和 DO 防重放记录，不触发原任务重跑。
